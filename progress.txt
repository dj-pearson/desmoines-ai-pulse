# Codebase Patterns

## Tech Stack
- React 18.3.1 + TypeScript 5.5.3 + Vite 5.4.1
- Supabase (PostgreSQL, Auth, Edge Functions, Storage, Realtime)
- Tailwind CSS + shadcn/ui (Radix primitives) + Lucide icons
- TanStack Query v5 for server state
- React Router DOM v6 for routing
- Stripe for payments (subscriptions + campaigns)
- Playwright for E2E testing (7 suites)
- Cloudflare Pages for hosting

## Project Structure
- src/components/ui/ — shadcn/ui base components (do NOT modify these directly)
- src/components/[feature]/ — feature-specific components
- src/hooks/ — 103 custom hooks (use-*.ts naming)
- src/lib/ — utility libraries (errorHandler, safeStorage, utils)
- src/contexts/ — React contexts (AuthContext is the primary one)
- src/pages/ — 62 route page components
- src/integrations/supabase/ — Supabase client + generated types
- supabase/functions/ — 76 edge functions with _shared/ middleware
- supabase/migrations/ — 151 SQL migrations

## Key Conventions
- Environment variables: use import.meta.env (NOT process.env) — Vite project
- localStorage: use safeStorage wrapper from @/lib/safeStorage (NOT direct access)
- Error handling: use handleError/withErrorHandling from @/lib/errorHandler
- Auth: use useAuth() from @/contexts/AuthContext
- Subscriptions: use useSubscription() hook + PremiumGate component
- Named exports preferred over default exports (except pages)
- 2-space indentation, single quotes, semicolons

## Build & Quality Commands
- npm run dev — dev server on localhost:8080
- npm run build — production build (strips console.* via esbuild)
- npm run lint — ESLint
- npm run type-check — TypeScript (relaxed mode)
- npm run type-check:strict — TypeScript (strict mode, partial files)
- npm run validate — lint + typecheck combined
- npm test — Playwright E2E tests

## Edge Function Patterns
- CORS middleware from _shared/cors.ts
- Rate limiting from _shared/rateLimit.ts (100 req/15min default)
- Input validation from _shared/validation.ts
- 18 functions have verify_jwt=false (scrapers, crawlers, webhooks)

## Database Patterns
- RLS enabled on all tables
- Public read for content tables (events, restaurants, attractions)
- Authenticated write with role checks
- Admin-only for sensitive operations
- Auto-update timestamps via triggers

- **Learnings for future iterations:**
  - Apple App Store deep link `https://apps.apple.com/account/subscriptions` works on iOS Safari + macOS; falls back to the marketing page on other browsers — accept that and don't bother with itms-apps:// (which doesn't work in many browser contexts).
  - For App Intents that only need to land the user inside the app with
    captured parameters, the cleanest pattern is `openAppWhenRun = true`
    + post payload to an @Observable dispatcher the SwiftUI views
    observe. Lets the navigation logic stay in the view layer.
  - SFSpeechRecognizer permission and AVAudioApplication.requestRecordPermission are TWO separate gates — checking only one leaves you with a non-functional mic in production.
  - Open-Meteo's WMO weather codes are dense; bucketing them up front into 6 ribbon-friendly conditions (clear/cloudy/rain/snow/fog/thunder) is far easier than carrying 100 templates.
  - For Postgres functions that return the same column shape across multiple "modes" (For You vs Trending), keeping the RETURNS TABLE definition identical lets the iOS decoder swap RPCs without code changes.
  - On the swipe-personalization RPC, the random jitter (`+ random() * 5`) is what makes "refresh" feel responsive — without it the UI shows the same top-N every time even though the underlying score is unchanged.
  - When supporting anon participants in a multiplayer feature, make user_id nullable + add a CHECK that at least one identity field is set. Don't try to create a fake auth user — Supabase RLS gets confused by it later.

## 2026-05-06 — Ralph Loop 17: Cross-Platform Subscription Sync (SUB-SYNC-009, SUB-SYNC-010, SUB-SYNC-011)

Three iterations on the cross-platform subscription sync stack so iOS,
Android, and web (Stripe) subscription state stays consistent across all
three storefronts.

- **SUB-SYNC-010**: Apple App Store Server Notifications v2 webhook
  - New edge function `supabase/functions/appstore-server-notifications-v2/index.ts`
  - Verifies the signedPayload JWS using Apple's PKI: validates the x5c root CA fingerprint against Apple Root CA G3, and verifies the JWS signature with the leaf certificate's ES256 public key (custom ASN.1 SPKI extraction since some Deno targets don't accept full DER cert as `spki`)
  - Decodes notificationType, subtype, notificationUUID, and the embedded signedTransactionInfo + signedRenewalInfo JWSes
  - Handles SUBSCRIBED, DID_RENEW, DID_CHANGE_RENEWAL_STATUS (auto-renew toggle via subtype), DID_FAIL_TO_RENEW, EXPIRED, REVOKE, REFUND, GRACE_PERIOD_EXPIRED
  - Looks up `user_subscriptions` by `apple_original_transaction_id` scoped to `platform=ios` and updates status / current_period_end / cancel_at_period_end / apple_transaction_id / plan_id
  - New table `apple_notification_log` for at-least-once idempotency (Apple retries 5×); keyed by Apple's `notificationUUID`
  - Migration: `supabase/migrations/20260506000004_apple_notification_log.sql`

- **SUB-SYNC-011**: Google Play Real-Time Developer Notifications webhook
  - New edge function `supabase/functions/play-rtdn-webhook/index.ts`
  - Verifies the OIDC bearer token Google attaches to push messages: alg=RS256, fetches Google's JWKS (cached 1 hour), verifies signature with the matching kid's public key, validates iss (accounts.google.com), aud (PLAY_RTDN_AUDIENCE env), and exp
  - Decodes the base64 Pub/Sub message into a DeveloperNotification — handles both `subscriptionNotification` and `voidedPurchaseNotification` paths
  - Re-uses GOOGLE_PLAY_SERVICE_ACCOUNT_KEY to call `purchases.subscriptions.get` for fresh state (expiry, autoRenewing, orderId)
  - Handles SUBSCRIPTION_PURCHASED / RENEWED / RECOVERED / RESTARTED / CANCELED / ON_HOLD / IN_GRACE_PERIOD / PAUSED / REVOKED / EXPIRED
  - New table `play_rtdn_log` for at-least-once idempotency keyed by Pub/Sub `messageId`
  - Migration: `supabase/migrations/20260506000005_play_rtdn_log.sql`

- **SUB-SYNC-009**: One-shot data fix — split legacy mixed-platform subscription rows
  - Migration `supabase/migrations/20260506000006_split_legacy_mixed_platform_subs.sql`
  - For each `user_subscriptions` row with `platform IN ('ios', 'android')` AND `stripe_subscription_id IS NOT NULL`:
    - Inserts a fresh `platform='web'` row carrying the Stripe identifiers + canonical period/status/plan_id
    - Clears `stripe_subscription_id` and `stripe_customer_id` from the original mobile row
  - Idempotency via `WHERE NOT EXISTS` against the per-user `platform='web'` row, plus `ON CONFLICT DO NOTHING` on the audit table
  - New `subscription_split_audit` table maps legacy → web rows for traceability and rollback
  - Deployment checklist, manual reconciliation queries, and rollback procedure documented in `DEPLOYMENT.md` (Subscription Sync — Cross-Platform Cleanup section)

- **Learnings for future iterations:**
  - Deno's WebCrypto subtle.verify accepts JWS-format raw r||s ECDSA signatures directly (no DER conversion needed for verification). Only signing returns DER on some runtimes.
  - Apple's x5c chain verification requires extracting the SPKI from the leaf cert via ASN.1 walking — `crypto.subtle.importKey('spki', certBytes, ...)` on the full cert fails on Deno because the cert is wrapped in a SEQUENCE and importKey expects a bare SubjectPublicKeyInfo.
  - For Pub/Sub OIDC verification, Google's JWKS at `https://www.googleapis.com/oauth2/v3/certs` rotates ~daily — cache for ≤1 hour and refetch on `kid` miss.
  - Apple notificationUUID + Pub/Sub messageId are both safe idempotency keys; both providers redeliver with the same id on retry.
  - When splitting subscription rows, query the post-state via `WHERE NOT EXISTS` rather than a temp table — keeps the migration single-statement-friendly and idempotent against partial reruns.
  - The legacy mixed-row issue was a write scope bug in the validate-receipt functions; the fix in 20260506000006 is one-shot. Re-introducing platform-unscoped UPDATEs anywhere in those edge functions will recreate the data corruption.

(fetchTextWithSizeCap, 200KB) on the page fetch. Read-only; returns

### What shipped

  enable: a failed transformed source retries once with the original (bare) URL
  before ever showing the placeholder — "a failed transform falls back to the

  endpoint (which genuinely resizes/re-encodes) and returns external URLs
  unchanged. srcset + modern-format sources are gated on `transformable`.

  on the three content list-cards (EventCard, RestaurantCard, Attractions card)
