## 2026-08-31 - SEO-027 raised (entity prerender coverage)

Found while verifying SEO-021, not by the audit, which got it wrong.

The 2026-08-31 audit in prd-seo-organic.json claimed entity prerendering "landed
and works" from a 3-URL sample. All three sat near the front of the render order.
The build log is explicit: order is pseo(14) -> attractions(22) -> playgrounds(67)
-> articles(18) -> guides(4) -> restaurants(477) -> events(525), budget 420s, and
267 prerendered against 860 over budget - events 525/525 (ALL), restaurants
335/477. Strict gate: 0 rejections, so nothing failed, it ran out of time.

Confirmed on production with curl -A GPTBot: /events/blue-october-... and
/restaurants/zombie-burger-drink-lab both return the homepage title, ld+json 0.

Arithmetic that constrains the fix: 267 entities in 420s is ~0.64/sec, so all
1,127 is ~1,770s for entities alone, ~31 min with the rest of the build, against
a 20-minute Cloudflare Pages build timeout. Raising the budget alone cannot fit.
Concurrency or incremental rendering is the lever.

**Learnings for future iterations:**
- Sample the END of a sitemap, not the start. Render order and alphabetical order
  conspire to make a front-of-list sample always look healthy.
- A warning line in a build that exits 0 is invisible. Coverage regressions need
  an assertion, not a printed warning.
