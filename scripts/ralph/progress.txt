## 2026-08-22 - WEB-SEO-017 + WEB-CI-025 (CI was not broken, it was unplugged)
Both priority-1 CI stories turned out to share one cause nobody had looked for: secrets in an environment scope no workflow declared.

Files changed:
- .github/workflows/event-crawler.yml - `environment: Scrape` on crawl-events and on update-ai-config, with the why inline.
- prd.json - branchName retargeted to claude/prd-p1-loop (claude/web-platform-autonomy is 556 behind main and holds a different PRD); WEB-SEO-017 and WEB-CI-025 notes rewritten with the root cause and the remaining blockers.
- scripts/ralph/progress.txt - two new Codebase Patterns (gh default repo, split secret scopes) + corrected the PRD-location pattern.

Repo settings changed (not files):
- `gh workflow enable pr-checks.yml` and `gh workflow enable event-crawler.yml` - both were state=disabled_manually, both now active.
- `gh repo set-default dj-pearson/desmoines-ai-pulse`.

Evidence:
- WEB-CI-025 AC5: npm run validate exit 0 (0 errors, 5111 warnings); npm run build exit 0, vite 23.4s, prerender 35/35 hub routes, 0 failed. Main is green.
- WEB-SEO-017 AC4: eight consecutive scheduled crawler failures 2026-02-05..2026-02-12, each ~1m45s, then disabled on 2026-02-12. Uniform duration = same early step every time.
- Root cause: crawlers/catchdesmoines_crawler.py:90 raises "SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY must be set". Those secrets are environment-scoped to Scrape; crawl-events declared no environment.

**Learnings for future iterations:**
- A story that says a workflow is "switched OFF" is describing the symptom. Ask what it was doing before it was switched off - `gh run list --workflow=X` survives the disable and the uniform ~1m45s duration across eight runs is what pointed at a single early step rather than flaky scraping.
- Expired logs are not a dead end. `gh run view --log-failed` returns HTTP 410 after ~90 days, but `gh run view --json jobs` still returns job names and conclusions forever. "Lint & Typecheck failed, Build skipped" was enough to date the pr-checks failure to a workflow structure that no longer exists.
- Secret existence is not secret reachability. `gh secret list` showed SUPABASE_URL present and looked fine; the two keys that mattered were invisible to that command because they are environment secrets. Always check `gh api repos/.../environments/<name>/secrets` too.
- Before adding `environment:` to a job, check `protection_rules` and `deployment_branch_policy` on that environment. Scrape has neither, so it adds no approval gate - an environment with required reviewers would silently park every scheduled run in a pending approval instead.
- Next: WEB-SEO-017 AC2 cannot fully pass until CLOUDFLARE_DEPLOY_HOOK_URL exists (publish-freshness warns and exits 0 without it, so a successful crawl still reaches no crawler). WEB-CI-025 AC4 needs a throwaway PR to confirm the check reports. Both need a human.
