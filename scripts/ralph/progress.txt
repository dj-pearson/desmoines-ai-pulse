## 2026-09-02 — WEB-PERF-028 (list hooks onto TanStack Query)

Closed the story that had been left open across two ticks. Six hooks converted

## 2026-09-02 — WEB-SEC-031 (logout cache teardown) and WEB-SEC-030 (role sync)

### Learnings for future iterations

- **A logout handler that returns early never sees its own event.** AuthContext's
  `handleAuthChange` opens with `if (isLoggingOutRef.current) return;`, and the
  flag is set before `signOut()`. So the SIGNED_OUT raised by the logout button
  is dropped before its handler runs. Anything that must happen on sign-out
  belongs in both the event branch and `logout()`. Check for that early return
  before deciding one hook is enough.
- **`queryClient.clear()` beats a prefix list.** A list of user-scoped key
  prefixes is a second inventory to keep in step with a hundred hooks, and its
  failure mode is silent. Clearing everything costs one refetch on a screen the
  user is leaving.
- **Most user-scoped keys were already correct.** The audit found two wrong out
  of a dozen. The real residue was admin- and role-scoped keys, which should NOT
  carry a user id; `clear()` is the only thing that reaches those.

  argument and reads the id inside its queryFn via `supabase.auth.getUser()`,

  `auth.getUser` and `p_user_id`, not just hook signatures.
- **Prefer `useAuthState()` over `useAuth()` in hot hooks.** The context split
  exists so an ads hook on every page does not re-render when an action
  reference changes.
- **`/TO public/` matches `INSERT INTO public.x`.** A migration assertion about
  grants has to anchor on GRANT. This is the same class as the
  comment-vs-assertion trap: the regex is right about the words and wrong about
  the meaning.
- **Tighten an RPC only after counting its callers.** `sync_oauth_user_role` had

  backward-compatibility rules rather than a breaking change for shipped
  binaries.
- **Confirm both ends of an email match.** Requiring `email_confirmed_at` on the
  target is the obvious half; requiring it on the row the role is copied FROM is
  the half that stops someone seeding a role at an admin's address with an

## 2026-09-02 — WEB-SEC-033 (deals ownership and redemption ledger)

### Learnings for future iterations

- **A policy's NAME is not its predicate.** "Business owners and admins can
  insert deals" had `WITH CHECK (auth.role() = 'authenticated')`. The name is
  why nobody looked. Read predicates, not policy names.
- **PERMISSIVE policies OR together.** Adding a stricter policy beside a
  permissive one changes nothing. The permissive one has to be DROPped.
- **PostgREST resolves RPC arguments by name, so parameter names are contract.**
  Renaming `deal_id` would break iOS (`let deal_id: String`) and Android
  (`@SerialName("deal_id")`) even though the type and arity are unchanged. Keep
  the name and qualify the shadowed column as `function_name.param`.
- **Do not add an optional parameter beside an existing arity.** A
  two-parameter version with a DEFAULT lives alongside the one-parameter
  function, and a one-argument call is then ambiguous — the PGRST203 failure
  that broke `get_active_ads` on every homepage load.
- **Derive a counter, don't increment it.** A ledger plus `count(*)` makes
  retries, double-submits and replays converge. An increment accumulates, and
  once it has, nothing can tell an inflated count from a real one.
- **An unsalted hash of an IP is not anonymisation.** IPv4 is 32 bits; brute
  force reverses it in seconds. Salt it, and keep the salt in a table with RLS
  on and no policies.
- **CLAUDE.md's tightening rule has one exception: a write no shipped client
  performs.** That is a claim to verify with grep and then pin with a test, not
  to assert in a comment.

## 2026-09-02 — WEB-AUTH-007 and WEB-AUTH-012 (session policy, credential changes)

### Learnings for future iterations

- **`signOut({ scope: 'global' })` on a timeout signs the user out of every
  device.** A stale desktop tab ejecting someone from their phone is a bug that
  looks like a policy. A deliberate Log Out should stay global; a timeout should
  be `local`.
- **`Date.now()` at mount is page-load age, not session age**, and it is wrong
  in both directions: a reload restarts the cap, and a long-open tab with a
  fresh session hits it. Measure from `user.last_sign_in_at`.
- **Not `iat`.** It is reissued on every refresh, Supabase refreshes hourly, so
  an 8-hour cap read from `iat` is unreachable. Keep it only as a fallback where
  it can only make the cap more generous.
- **Return null when a measurement is unknown.** Falling back to `now()` silently
  restores the behaviour being replaced, and does it invisibly.
- **`enabled: isAdmin` alone is wrong while the admin check is in flight.**
  `isAdmin` is false until it resolves, so the clock would start at an arbitrary
  point after load. Gate on `isAdmin && !isAdminLoading`.
- **`updateUser({ password })` accepts any live session.** Without
  re-authenticating first, an unlocked laptop or a stolen token takes the
  account over permanently. Re-auth, then change, then revoke other sessions —
  and `scope: 'others'`, not `'global'`, so the user is not ejected from the
  screen they just used.
- **Revoking other sessions is the point of a password change.** Changing it
  because it may be compromised achieves nothing while old sessions stay valid.
- **Supabase email change is double-confirmation by default, and the UI has to
  say so.** A user who confirms one inbox and stops will otherwise believe the
  change failed.
- **Two files importing only each other are dead.** Grep for external importers
  before deleting, then pin the deletion with a test so they cannot creep back.

- **Learnings for future iterations:**
  - **A JSX comment cannot be the first thing after `return (`.** `return ( {/* ... */} <section>...)` is a syntax error - the braces are an expression container, and two sibling expressions have no fragment around them. I wrote exactly that, and the only thing that caught it was `check-error-handling` reporting "1 file failed to parse and was NOT checked" - eslint's own run stayed quiet. Put the note **above** `return` as a `//` comment.

An unknown name matches none, so overload resolution falls back across all ~250 tables and every downstream `.select()/.eq()/.order()` re-instantiates over a 250-member `SelectQueryError<...>` union. This is why one `Promise.all` in EnhancedArticleEditor costs 122 seconds. It also means the WEB-QA-017 burndown and the type-check perf story are ONE job - the same queries, in the same files, for the same reason.
  - **Measure the suspect before optimising it, and be willing to lose.** I refactored those three queries out of `Promise.all` into annotated `Promise<T[]>` loaders, which is the textbook fix. 89.21s -> 92.84s and three new errors. The tuple was never the cost; the table name was. A single-file tsconfig (`extends` app, `"include": []`, `"files": [one]`) turns a 21-minute experiment into a 90-second one - build that harness FIRST.
  - **A trace is readable before it finishes.** trace.json streams one JSON object per line, so a partial file parses if you salvage line by line. Attribute wall clock by sorting events by duration and greedily keeping non-overlapping spans - nesting otherwise double-counts `checkExpression` into the thousands of seconds.

It type-checked; it broke the test that pins the null on purpose. PostgREST resolves a function by the SET OF ARGUMENT NAMES supplied, so an omitted key can select a different overload or 404 PGRST202 - and Supabase's generator drops nullability on every `DEFAULT NULL` argument, so the generated type was the wrong side of that argument. When a test asserts the opposite of your fix, read the test before you change it.

## 2026-09-18 - WEB-CI-031 AC4 follow-up: the nightly would have been red on day one
Confirming a new scheduled check before trusting it found two regressed files and one live defect.
- `src/pages/Auth.tsx:790` read `onClick={handleResendVerification}`, and that handler's first parameter is `email: string = signupEmail`. onClick passes the React MouseEvent as the first argument, so the default never applied and the "Resend Verification Email" button called resendVerificationContext with a synthetic event. The other call site already wrapped it in an arrow.
- Three `onCheckedChange` handlers passed Radix's `CheckedState` (`boolean | "indeterminate"`) to a boolean parameter; the termsAccepted checkbox 15 lines below already coerced with `!!checked`.
- `interestTiles.test.tsx` carried a `@ts-expect-error` that had become TS2578 itself.
- **Learnings for future iterations:**
  - **Run a new CI check once before committing the workflow that runs it.** I reasoned correctly that my own edits could not add app-project errors (strictNullChecks is off there, so null is assignable everywhere) and that reasoning was sound - and irrelevant, because the baseline was already stale by two files I had never touched. A baseline is a claim about a moment, not a property of your diff.
  - **`onClick={handler}` where the handler has an optional first parameter is a silent bug, not a style choice.** React hands the event to it. Any `(x = default) => ...` used bare as onClick gets the MouseEvent instead of the default, forever, with no runtime error - the call just goes out with nonsense. Grep for `onClick={handle` next to handlers with defaulted parameters.
  - **I put a `//` comment between JSX attributes again.** progress.txt already records this exact lesson from WEB-PERF-029. Inside an opening tag every token is an attribute, so `//` is parsed as JSX, not as a comment. The note goes ABOVE the element as `{/* ... */}`, or above the whole statement as `//`. That is now twice for the attribute position and once for the `return (` position - three variants of one mistake.
  - A `@ts-expect-error` that stops being needed becomes an error itself (TS2578). That is the directive working: here it fired because Radix's Checkbox accepts `onChange` through its HTML props passthrough, which is exactly why the mistake being reproduced compiles and silently does nothing.
