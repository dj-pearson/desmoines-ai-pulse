## 2026-06-13 - WEB-AUTO-005 (Duplicate venue/event detection with auto-link + merge queue)
Cross-database dedupe now runs itself weekly; only ambiguous pairs reach a human.

What was implemented:
- **New `dedupe-content` edge fn** (weekly cron Mon 03:15 UTC, jobRunner-wrapped, Job Health re-runnable): pulls trigram-candidate pairs from the detection RPCs for events + restaurants, then auto-merges high-confidence pairs and queues the 70–90% middle. Counts (pairs/autoMerged/queued/skipped/errors) → automation_job_runs.
- **Detection RPCs** `find_duplicate_events` / `find_duplicate_restaurants`: pg_trgm `%` self-joins (GIN index from 20250107000007) + haversine distance + same-date gate (events) + per-row richness so the survivor is chosen with no extra query.
- **Auto-merge gate:** name_sim>=0.9 AND (events: same date AND <=150m-or-no-coords; restaurants: <=150m, proximity REQUIRED → same-name franchises far apart never auto-merge). Restaurants with no coords / >400m apart aren't queued either (franchise guard).
- **`merge_duplicate_content()`** SECURITY DEFINER RPC: generic single-column FK repoint loop (loser→survivor) with ctid fallback dropping only true collisions; keeps the richer row; marks loser `is_merged` (RETAINED); writes immutable `content_merges` audit row. **`unmerge_content()`** reverses within 30 days. **`dismiss_merge_candidate()`** for not-a-duplicate.
- **Admin → Content → Duplicates tab** (`MergeReviewPanel`): side-by-side Keep/Remove cards, % match + distance chips, Merge / Swap-which-to-keep / Not-a-duplicate, Run-scan button.
- **Browse filter:** useEvents + useRestaurants add `.neq('is_merged', true)`; `get_rotated_restaurants` re-created with an `is_merged=false` guard (the default restaurant path returns full rows, so the hook filter alone wasn't enough).

Learnings for future iterations:
- The big design here was already validated on the sibling branch — its prd notes were a goldmine. When a story exists on both branches, read the other branch's DONE notes for the proven approach.
- `get_rotated_restaurants` is a trap for ANY restaurant browse-visibility filter: it returns full jsonb rows and ignores client `.neq()`. Filter inside the RPC.
- types.ts edits: anchor on TABLE-UNIQUE field names (events `ai_writeup`, restaurants `ai_writeup`+`city`) and the Row/Insert/Update keyword line — the trailing fields (`writeup_prompt_used`, etc.) repeat across events/restaurants/attractions and won't match uniquely.
- Auto-merge proximity is REQUIRED for restaurants (franchise safety) but OPTIONAL for events (a no-coords same-title same-date pair is almost certainly the same event from two sources).
