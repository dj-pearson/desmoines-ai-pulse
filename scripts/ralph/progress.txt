- **Learnings for future iterations:**
  - Confirmed on all three: ALWAYS give useQuery an explicit generic naming the

  - Compare tsc error count AND per-file distribution to a baseline after each

## 2026-09-02 — WEB-PERF-028 (list hooks onto TanStack Query)

Closed the story that had been left open across two ticks. Six hooks converted
(attractions, playgrounds, articles, profile, restaurants, hotels), plus the
three smaller hooks living in useHotels.ts. Hotel list projection added, both
remaining client-side-filtering pages moved onto server-side filters.

### Learnings for future iterations

- **PrerenderSignal only counts TanStack queries.** `useIsFetching()` is the
  source of `data-queries-settled`. Any hook that fetches outside TanStack is
  invisible to it, so the route claims settled mid-flight and the prerenderer
  captures a skeleton. This is the reason the conversion mattered; the caching
  was the smaller half.
- **Always give useQuery an explicit generic naming the Row type.** These hooks
  select a column projection, so an inferred return type is narrower than the
  Row callers are typed against. One conversion produced 34 errors in two files
  for a change that altered no runtime value.
- **Do not write a generic hook-converter script.** It worked on the first hook
  and then ate a `try {` opener on the second, because each hook's catch block
  is shaped slightly differently. Hand-convert; it is faster than debugging the
  script.
- **Client-side filtering is usually held in place by the filter dropdowns.**
  Both pages derived their facet lists and "Browse By" counts from the same
  unfiltered array they were filtering. You cannot move the filters to the
  server until the facets have their own query. Look for that dependency first.
- **Collapsing a sort memo can drop behaviour hiding at the end of it.** The
  Attractions sort memo ended in `arrangeSponsored(sorted)`. Deleting the memo
  deleted the sponsored boost. `git show HEAD:<file>` on any memo before
  replacing it.
- **A column projection is a contract with every function that reads the row.**
  ATTRACTION_LIST_COLUMNS omitted is_sponsored and sponsored_until, so the
  sponsored boost on /attractions had never once fired. It type-checked,
  because the projection's absence is not a type error. When adding a
  projection, grep for every helper the list is passed to.
- **The comment-vs-assertion trap, twice more.** `assertFalse(/useAttractions\(\{\}\)/)`
  matched my own comment saying "this used to be useAttractions({})". Reword
  the prose. Never weaken the assertion.
- **PostgREST cannot substring-match inside a text[].** `cs` wants a whole
  element and `ilike` does not apply to arrays. The /playgrounds search matches
  inside amenity strings, so that one filter has to stay client-side; moving it
  would have silently dropped every amenity hit.

## 2026-09-02 — WEB-SEC-031 (logout cache teardown) and WEB-SEC-030 (role sync)

### Learnings for future iterations

- **A logout handler that returns early never sees its own event.** AuthContext's
  `handleAuthChange` opens with `if (isLoggingOutRef.current) return;`, and the
  flag is set before `signOut()`. So the SIGNED_OUT raised by the logout button
  is dropped before its handler runs. Anything that must happen on sign-out
  belongs in both the event branch and `logout()`. Check for that early return
  before deciding one hook is enough.
- **`queryClient.clear()` beats a prefix list.** A list of user-scoped key
  prefixes is a second inventory to keep in step with a hundred hooks, and its
  failure mode is silent. Clearing everything costs one refetch on a screen the
  user is leaving.
- **Most user-scoped keys were already correct.** The audit found two wrong out
  of a dozen. The real residue was admin- and role-scoped keys, which should NOT
  carry a user id; `clear()` is the only thing that reaches those.
- **A key can be user-scoped without looking it.** `useActiveAds` takes no user
  argument and reads the id inside its queryFn via `supabase.auth.getUser()`,
  passing it to an RPC that frequency-caps per account. Grep queryFn bodies for
  `auth.getUser` and `p_user_id`, not just hook signatures.
- **Prefer `useAuthState()` over `useAuth()` in hot hooks.** The context split
  exists so an ads hook on every page does not re-render when an action
  reference changes.
- **`/TO public/` matches `INSERT INTO public.x`.** A migration assertion about
  grants has to anchor on GRANT. This is the same class as the
  comment-vs-assertion trap: the regex is right about the words and wrong about
  the meaning.
- **Tighten an RPC only after counting its callers.** `sync_oauth_user_role` had
  exactly one, already passing `auth.uid()`, and neither mobile app called it.
  That is what made narrowing its validation legal under CLAUDE.md's
  backward-compatibility rules rather than a breaking change for shipped
  binaries.
- **Confirm both ends of an email match.** Requiring `email_confirmed_at` on the
  target is the obvious half; requiring it on the row the role is copied FROM is
  the half that stops someone seeding a role at an admin's address with an
  unconfirmed row and then inheriting it.

## 2026-09-02 — WEB-SEC-033 (deals ownership and redemption ledger)

### Learnings for future iterations

- **A policy's NAME is not its predicate.** "Business owners and admins can
  insert deals" had `WITH CHECK (auth.role() = 'authenticated')`. The name is
  why nobody looked. Read predicates, not policy names.
- **PERMISSIVE policies OR together.** Adding a stricter policy beside a
  permissive one changes nothing. The permissive one has to be DROPped.
- **PostgREST resolves RPC arguments by name, so parameter names are contract.**
  Renaming `deal_id` would break iOS (`let deal_id: String`) and Android
  (`@SerialName("deal_id")`) even though the type and arity are unchanged. Keep
  the name and qualify the shadowed column as `function_name.param`.
- **Do not add an optional parameter beside an existing arity.** A
  two-parameter version with a DEFAULT lives alongside the one-parameter
  function, and a one-argument call is then ambiguous — the PGRST203 failure
  that broke `get_active_ads` on every homepage load.
- **Derive a counter, don't increment it.** A ledger plus `count(*)` makes
  retries, double-submits and replays converge. An increment accumulates, and
  once it has, nothing can tell an inflated count from a real one.
- **An unsalted hash of an IP is not anonymisation.** IPv4 is 32 bits; brute
  force reverses it in seconds. Salt it, and keep the salt in a table with RLS
  on and no policies.
- **CLAUDE.md's tightening rule has one exception: a write no shipped client
  performs.** That is a claim to verify with grep and then pin with a test, not
  to assert in a comment.

## 2026-09-02 — WEB-AUTH-004 (signup with an existing address)

### Learnings for future iterations

- **Supabase signUp does not error for an existing address.** It returns a user
  and no session, identical to a fresh signup, so the response cannot enumerate
  accounts. The only difference is `identities: []`. Anything reading
  `user && !session` conflates the two.
- **The consequence was a button that fails on press.**
  `auth.resend({ type: 'signup' })` errors for a confirmed address, so the
  Resend button was broken for exactly the user who saw it.
- **Keep the screen neutral, change the actions.** Naming the account is the
  enumeration the response shape protects against. Swapping Resend for
  "Sign in instead" and "Reset your password" reads the same to anyone.
- **Treat a missing `identities` as a normal signup.** If the field ever
  disappears from supabase-js, the neutral screen with a working Resend is the
  safer wrong answer; the alternative hides Resend from every real new user.
- **Extract the decision as a pure function.** "Test both branches" is only
  cheap once the branch is a function over a response shape rather than a line
  inside a useCallback.

## 2026-09-02 — WEB-BE-034 AC3 (two unpublish switches on events)

### Learnings for future iterations

- **`events` has TWO independent hide mechanisms and they had split by
  audience.** `is_hidden`/`hidden_at` is read by 19 web surfaces and nothing
  else; `archived_at` is read by 5 agent surfaces and nothing else. So the
  expired-event sweep could run perfectly and change nothing a visitor or a
  crawler saw. When a job "does nothing", check whether the readers agree with
  the writer before blaming the schedule.
- **Check the column exists before a sweeping `.is()` edit.** A filter on a
  missing column is 42703, and PostgREST fails the whole select — the WEB-QA-003
  failure that blanked the homepage. All 19 sites here read `events`, which
  carries both columns.
- **A mechanical edit across N chains cannot assume how each terminates.** Two
  of the 19 sat inside a `Promise.all` array and ended in a comma, not a
  semicolon; appending a chained call after them was a syntax error. eslint
  caught it. Run lint immediately after any scripted multi-file edit.
- **The comment-vs-assertion trap, third variant: it can fail on CORRECT code.**
  The test counted `.neq("is_hidden", true)` per file and useHomepageStats'
  docstring QUOTES that call to explain what the hook must match. Strip block
  and line comments before counting anything in source.
- **Count paired filters, don't just check presence.** Asserting both filters
  appear somewhere in a file passes even when one query has both and another has
  neither. Asserting the counts are EQUAL is what catches the drift.
- **Don't merge the two mechanisms.** "A moderator hid this" and "the sweep
  retired this" are different facts, and `archived_at` is a timestamp because
  the documented undo is "set it back to null" — a boolean would lose when it
  happened.

### Finding, not acted on: an unwired test suite

`supabase/functions/_tests/agent-performance-review.test.ts` appears in no
workflow. Run by hand it dies with `NotCapable: Requires net access to

## 2026-09-02 — WEB-AUTH-003 and WEB-AUTH-005 (consent binding, verification landing)

### Learnings for future iterations

- **`signUp` with confirmation on returns a user and no session.** Anything the
  client does immediately after it runs with `auth.getUser()` === null. That is
  why the consent rows were written with `user_id = NULL`, and why the record
  meant to prove consent was invisible to the export that keys on `user_id`.
- **The data was already in the right place; only the writer was wrong.**
  Auth.tsx has always sent the consent block in signup metadata, so moving the
  write into `handle_new_user` needed no client change at all. Check what the
  metadata already carries before adding a parameter.
- **Never match a client-supplied hash against a client-supplied id.** The
  adoption function recomputes the email hash from `auth.users.email`. Same
  class of bug as WEB-SEC-030.
- **Only a confirmed address may claim rows.** Adopting on an unconfirmed one
  lets anyone who can type an address inherit consent recorded against it.
- **An append-only log must never trade a row for a unique index.** Two rows for
  one consent prove the same fact twice; a dropped row proves nothing. Mark the
  writer in metadata instead.
- **Supabase puts auth errors in TWO places.** PKCE and OAuth failures go in the
  query string; implicit-flow and email-link failures go in the URL FRAGMENT,
  which never reaches a server and which `useSearchParams` does not expose.
  Reading only one is how a fix stays half-broken.
- **Do not show Supabase's error description to a user.** "Email link is invalid
  or has expired" is written for a developer. Write the message, and pin with a
  test that the raw one never reaches the reader.
- **A resend response must be neutral.** `auth.resend` errors for an
  already-confirmed address, so reporting the outcome turns the page into an
  account checker.
- **"No error" is not "confirmed".** Someone opening the page from history has
  neither, and celebrating for them is the same defect more quietly. Three
  states, not two.
- **No countdown on an error screen.** Redirecting away removes the one page
  that explains what happened and holds the action needed.

## 2026-09-02 — WEB-AUTH-006 (billing stops before erasure)

### Learnings for future iterations

- **Erasure order is a correctness property, not a style choice.**
  `user_subscriptions` is in PURGE_TABLES and is the only mapping to the Stripe
  customer, so a cancellation attempted after the purge has nothing to cancel
  and no way to find the customer (the email is gone too).
- **`grep -ci stripe` on the deletion function returned 0.** A one-word grep
  found a story's whole premise. Worth running against any function whose job
  is to undo something.
- **Take the client as a parameter, not an import.** Passing a `BillingClient`
  into `_shared/cancelBillingBeforeErasure.ts` is what lets seven of the eleven
  tests actually RUN the teardown against a fake — ordering, refusal, partial
  failure — instead of asserting about source text.
- **Refuse, don't continue, when billing teardown fails.** Continuing erases the
  mapping and leaves an active charge nothing can trace back. 409 with a code
  the client can branch on.
- **Deleting the Stripe customer matters as much as cancelling.** A customer
  left behind keeps the payment method and billing address — data the erasure
  was meant to remove.
- **An unknown subscription status should read as live.** A status this code has
  not seen is more likely a new active state than a new terminal one, and the
  safe error is a redundant cancel.
- **A store subscription cannot be cancelled server-side, so the UI must say
  so.** Apple and Google own it. Silence lets the user believe deleting the
  account stopped the charge — the same defect one platform over.

## 2026-09-02 — WEB-AUTH-007 and WEB-AUTH-012 (session policy, credential changes)

### Learnings for future iterations

- **`signOut({ scope: 'global' })` on a timeout signs the user out of every
  device.** A stale desktop tab ejecting someone from their phone is a bug that
  looks like a policy. A deliberate Log Out should stay global; a timeout should
  be `local`.
- **`Date.now()` at mount is page-load age, not session age**, and it is wrong
  in both directions: a reload restarts the cap, and a long-open tab with a
  fresh session hits it. Measure from `user.last_sign_in_at`.
- **Not `iat`.** It is reissued on every refresh, Supabase refreshes hourly, so
  an 8-hour cap read from `iat` is unreachable. Keep it only as a fallback where
  it can only make the cap more generous.
- **Return null when a measurement is unknown.** Falling back to `now()` silently
  restores the behaviour being replaced, and does it invisibly.
- **`enabled: isAdmin` alone is wrong while the admin check is in flight.**
  `isAdmin` is false until it resolves, so the clock would start at an arbitrary
  point after load. Gate on `isAdmin && !isAdminLoading`.
- **`updateUser({ password })` accepts any live session.** Without
  re-authenticating first, an unlocked laptop or a stolen token takes the
  account over permanently. Re-auth, then change, then revoke other sessions —
  and `scope: 'others'`, not `'global'`, so the user is not ejected from the
  screen they just used.
- **Revoking other sessions is the point of a password change.** Changing it
  because it may be compromised achieves nothing while old sessions stay valid.
- **Supabase email change is double-confirmation by default, and the UI has to
  say so.** A user who confirms one inbox and stops will otherwise believe the
  change failed.
- **Two files importing only each other are dead.** Grep for external importers
  before deleting, then pin the deletion with a test so they cannot creep back.

## 2026-09-02 — WEB-SEC-032 (embedded service_role key)

### Learnings for future iterations

- **A key committed inside a `CREATE OR REPLACE FUNCTION` body is in the
  DATABASE, not just in git.** Eleven migrations did that and no later migration
  replaced the functions, so the value was readable through
  `pg_get_functiondef` by anyone who could connect. Fixing only the tree would
  have looked complete and changed nothing.
- **Rewrite what is installed, not what the migrations say.** Reading
  `pg_get_functiondef`, regex-replacing the literal and `EXECUTE`ing the result
  beats reproducing five long legacy bodies by hand, catches definitions that
  have drifted, and cannot leak a value because it contains none.
- **Match on the SHAPE of a credential, never the value.** A generic
  `eyJ[A-Za-z0-9_.-]{30,}\.` pattern keeps the fixing file itself clean for
  scanners and catches the next key someone embeds.
- **Verify after rewriting and warn loudly if anything is left.** An
  unrecognised shape must not pass silently.
- **An allowlist that grows is a scanner reporting less every quarter.**
  Fifteen entries here covered exactly the files that had the problem. Removing
  them is part of the fix, not a follow-up.
- **Check what a blanket allowlist entry is actually covering.**
  `'''.*\.md'''` was described as "prefixes and placeholders, not live secrets";
  two markdown files carried a live key under it.
- **Sweep wider than the story lists.** It named six files; the repo-wide grep
  found three more, including an Android setup guide.
- **A script reading a key from env must refuse to run without it.** "Bearer
  undefined" is a worse failure than a clear one, because it looks like a server
  auth problem.
- **Editing applied history needs a header saying why.** Otherwise the next
  reader assumes it was a mistake.
