## 2026-09-02 — WEB-PERF-028 (list hooks onto TanStack Query)

Closed the story that had been left open across two ticks. Six hooks converted

## 2026-09-02 — WEB-SEC-031 (logout cache teardown) and WEB-SEC-030 (role sync)

### Learnings for future iterations

- **A logout handler that returns early never sees its own event.** AuthContext's
  `handleAuthChange` opens with `if (isLoggingOutRef.current) return;`, and the
  flag is set before `signOut()`. So the SIGNED_OUT raised by the logout button
  is dropped before its handler runs. Anything that must happen on sign-out
  belongs in both the event branch and `logout()`. Check for that early return
  before deciding one hook is enough.
- **`queryClient.clear()` beats a prefix list.** A list of user-scoped key
  prefixes is a second inventory to keep in step with a hundred hooks, and its
  failure mode is silent. Clearing everything costs one refetch on a screen the
  user is leaving.
- **Most user-scoped keys were already correct.** The audit found two wrong out
  of a dozen. The real residue was admin- and role-scoped keys, which should NOT
  carry a user id; `clear()` is the only thing that reaches those.

  argument and reads the id inside its queryFn via `supabase.auth.getUser()`,

  `auth.getUser` and `p_user_id`, not just hook signatures.
- **Prefer `useAuthState()` over `useAuth()` in hot hooks.** The context split
  exists so an ads hook on every page does not re-render when an action
  reference changes.
- **`/TO public/` matches `INSERT INTO public.x`.** A migration assertion about
  grants has to anchor on GRANT. This is the same class as the
  comment-vs-assertion trap: the regex is right about the words and wrong about
  the meaning.
- **Tighten an RPC only after counting its callers.** `sync_oauth_user_role` had

  backward-compatibility rules rather than a breaking change for shipped
  binaries.
- **Confirm both ends of an email match.** Requiring `email_confirmed_at` on the
  target is the obvious half; requiring it on the row the role is copied FROM is
  the half that stops someone seeding a role at an admin's address with an

## 2026-09-02 — WEB-SEC-033 (deals ownership and redemption ledger)

### Learnings for future iterations

- **A policy's NAME is not its predicate.** "Business owners and admins can
  insert deals" had `WITH CHECK (auth.role() = 'authenticated')`. The name is
  why nobody looked. Read predicates, not policy names.
- **PERMISSIVE policies OR together.** Adding a stricter policy beside a
  permissive one changes nothing. The permissive one has to be DROPped.
- **PostgREST resolves RPC arguments by name, so parameter names are contract.**
  Renaming `deal_id` would break iOS (`let deal_id: String`) and Android
  (`@SerialName("deal_id")`) even though the type and arity are unchanged. Keep
  the name and qualify the shadowed column as `function_name.param`.
- **Do not add an optional parameter beside an existing arity.** A
  two-parameter version with a DEFAULT lives alongside the one-parameter
  function, and a one-argument call is then ambiguous — the PGRST203 failure
  that broke `get_active_ads` on every homepage load.
- **Derive a counter, don't increment it.** A ledger plus `count(*)` makes
  retries, double-submits and replays converge. An increment accumulates, and
  once it has, nothing can tell an inflated count from a real one.
- **An unsalted hash of an IP is not anonymisation.** IPv4 is 32 bits; brute
  force reverses it in seconds. Salt it, and keep the salt in a table with RLS
  on and no policies.
- **CLAUDE.md's tightening rule has one exception: a write no shipped client
  performs.** That is a claim to verify with grep and then pin with a test, not
  to assert in a comment.

## 2026-09-02 — WEB-AUTH-007 and WEB-AUTH-012 (session policy, credential changes)

### Learnings for future iterations

- **`signOut({ scope: 'global' })` on a timeout signs the user out of every
  device.** A stale desktop tab ejecting someone from their phone is a bug that
  looks like a policy. A deliberate Log Out should stay global; a timeout should
  be `local`.
- **`Date.now()` at mount is page-load age, not session age**, and it is wrong
  in both directions: a reload restarts the cap, and a long-open tab with a
  fresh session hits it. Measure from `user.last_sign_in_at`.
- **Not `iat`.** It is reissued on every refresh, Supabase refreshes hourly, so
  an 8-hour cap read from `iat` is unreachable. Keep it only as a fallback where
  it can only make the cap more generous.
- **Return null when a measurement is unknown.** Falling back to `now()` silently
  restores the behaviour being replaced, and does it invisibly.
- **`enabled: isAdmin` alone is wrong while the admin check is in flight.**
  `isAdmin` is false until it resolves, so the clock would start at an arbitrary
  point after load. Gate on `isAdmin && !isAdminLoading`.
- **`updateUser({ password })` accepts any live session.** Without
  re-authenticating first, an unlocked laptop or a stolen token takes the
  account over permanently. Re-auth, then change, then revoke other sessions —
  and `scope: 'others'`, not `'global'`, so the user is not ejected from the
  screen they just used.
- **Revoking other sessions is the point of a password change.** Changing it
  because it may be compromised achieves nothing while old sessions stay valid.
- **Supabase email change is double-confirmation by default, and the UI has to
  say so.** A user who confirms one inbox and stops will otherwise believe the
  change failed.
- **Two files importing only each other are dead.** Grep for external importers
  before deleting, then pin the deletion with a test so they cannot creep back.

   assertion firing on exactly the string it exists to catch - worth more than
   a green first run, and worth recording rather than quietly rebuilding.

6. MEASURE THE LANE'S EXISTING FAILURES BEFORE CLAIMING YOURS ARE NEW OR NOT.
   174 passed / 16 failed. Stash, rebuild, re-run proved the same 16 fail on a

2026-09-20 - WEB-ADS-006: creative auto-review would have been worse deployed
================================================================================

The story is about a function that never runs: undeployed, its sweep parked
after ~4,320 404s a month, no caller in src/. The finding that mattered was in
the code nobody was running. brandSafe() returned safe:true on three paths that
moderated nothing, and the verdict was `reasons.length === 0` - so the first
successful deployment into an environment without ANTHROPIC_API_KEY would have
auto-approved every ad creative on a public site and logged each one as
creative_auto_approved.

Changed:
  supabase/functions/campaign-creative-review/decision.ts   new, the verdict
  supabase/functions/campaign-creative-review/index.ts      checked + two lists
  src/lib/creativeReviewVerdict.ts                          new, the four messages
  src/components/advertising/CreativeUploadForm.tsx         reads the verdict
  scripts/__tests__/creative-auto-review-decision.test.mjs  new, 31 checks
  src/lib/__tests__/creativeReviewVerdict.test.ts           new, 10 tests

Learnings for future iterations:

1. READ THE DEAD CODE ANYWAY. A story whose headline is "this never runs" makes
   it tempting to do only the plumbing and wait for the deploy. The plumbing was
   the small half. A feature that is broken while switched off is cheap; one
   that is wrong the moment it is switched on is not, and the only chance to
   find it is before somebody deploys it.

2. "FAILED OPEN" IN A NOTE IS A CONFESSION NOBODY READS. Two of the three paths
   literally returned `note: "... (failed open)"` and wrote it into
   auto_review_checks. The string was there, in the database, for months. What
   was missing was a caller that treated it differently from "ok" - so add the
   FIELD the caller can branch on (`checked`), not a better note.

3. `!x.includes("UNSAFE")` IS NOT A SAFETY CHECK. It reads an empty response, a
   truncated one and an API error page as safe. A verdict parser must require
   the positive token, not the absence of the negative one. Found only by
   writing out what the three fail-open paths had in common.

4. A CHECK THAT COULD NOT RUN IS NOT A REJECTION, AND ONE LIST CANNOT SAY BOTH.
   index.ts fed is_approved and rejection_reason from the same array, so
   "your ad failed" and "we could not check your ad" were the same message to
   the advertiser. Two lists, and rejection_reason NULL when nothing actually
   failed.

5. WHEN AN AC SAYS TO CALL SOMETHING, CHECK WHO IS ALLOWED TO. AC3 said the
   upload form should invoke the review. An AFTER INSERT trigger already does,
   and the handler opens with requireAdminOrApiKey because it does cost-bearing
   AI work. The form READS the verdict instead. Second story running where the
   obvious route was a locked door - and both times the right move was to say
   so in the notes rather than widen the lock.

6. BOUND A POLL BY WHAT HAPPENS WHEN THE ANSWER NEVER COMES. Six seconds, then
   "queued". With the function undeployed the verdict never arrives, so the
   unbounded version would hold every advertiser on a spinner in what is
   currently the permanent state.

7. CHECK THE FAR END BEFORE BUILDING IT. AC4 asks for the summary to reach the
   admin queue. AdminCampaignDetail.tsx has rendered auto_review_reasons since
   WEB-AUTO-010; putting the unavailable items in that same array finished the
   AC with no admin UI change at all.

2026-09-20 - WEB-ADS-008: approving an event submission published nothing
================================================================================

The admin approve button set user_submitted_events.status = 'approved' and told
the admin to "promote them from the existing /admin/content workflow", which has
no path for user_submitted_events. So every human approval since the queue
shipped published nothing, while four screens and one email said "approved". The
AI path did insert, mapping ten of the fifteen columns that carry the
organizer's own data.

  supabase/functions/triage-event-submission/index.ts        calls the RPC
  supabase/functions/notify-event-submission/index.ts        conditional claim

  scripts/__tests__/publish-submission-mapping.test.mjs      new, 35 checks
  tests/submission-live-link.spec.ts                         new, in the lane

Learnings for future iterations:

1. TEST THE COUNT, NOT THE NAMES. The bug was ten columns mapped out of
   fifteen. A check for the six missing ones passes forever and says nothing
   about the seventh somebody adds to the form next year. Comparing the two
   lists - the table's columns against what the INSERT reads - is the check
   that keeps working, and it needs an explicit exemption list for the columns
   that are the workflow's rather than the organizer's.

2. A PREVIOUS ITERATION LEFT AN INSTRUCTION AND IT WAS WORTH FOLLOWING TO THE
   LETTER. "Restore a liveness claim in the same commit that makes it true."
   The restored claim is conditional on the row lookup succeeding, so the
   sentence cannot be false the way the original was. Pinning the CONDITION
   rather than the wording is what makes the test survive a copy edit.

3. NO POSTGRES HERE, BUT THE GRAMMAR IS FREE. check-migrations-parse runs every
   migration through the real Postgres parser, so a 198-line PL/pgSQL function
   is syntax-checked even with no database. What that does NOT establish is
   behaviour, and the notes say so in those words rather than implying a green
   run.

4. THE REPO'S OWN GATES CAUGHT TWO OF MY MISTAKES. check-event-unpublish-filters
   (written two iterations ago) failed the new lookup for honouring is_hidden
   and not archived_at - an archived listing would still have been linked.
   check-schema-usage failed three references to the unapplied migration, which
   belong in PENDING_MIGRATIONS with the migration cited, not in
   schema-baseline.json, whose header says it must only ever shrink.

5. AN UNKNOWN COLUMN IS A COMPILE-TIME COST, NOT JUST A TYPE ERROR. Until the
   migration is applied, PostgREST's typings resolve the select to a
   SelectQueryError union and every chained .in()/.eq()/.is() re-instantiates
   over it until tsc gives up with TS2589. unknownTable.ts measured the same
   shape at 89s and 7.8M instantiations. Typing the builder at its edges is the
   fix; the cast carries a note saying to delete it once the types carry the
   column.

6. A BULK ACTION MUST NOT REPORT WORK IT DID NOT DO. Approving five submissions
   where two fail to publish marks three approved and says so, with the other
   two named and left pending. The version that marks all five and shows a
   success toast is the same class of bug as the one this story is about.

7. WHEN AN AC SAYS "or, decided and documented", DECIDE. AC3 offered "updates
   the linked events row" or "unpublishes until re-approved". Unpublish, because
   the edit is untriaged and the alternative hands a publish button to anyone
   who has had one event approved. Hidden, not deleted, so the URL survives.
