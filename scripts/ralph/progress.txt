## 2026-06-13 - WEB-PERF-004 (Image CLS elimination + right-sized responsive images)
List cards and detail heroes now fetch appropriately-sized images, with a robust transform→original→placeholder fallback.

What was implemented:
- **KEY FINDING:** the `image-transform` edge fn was a pure pass-through (returned the original bytes, no resize), so the pre-existing `?width=` contract saved nothing. Made it actually resize: best-effort ImageScript (pure-WASM) via a GUARDED dynamic import — decodes JPEG/PNG only, never upscales, re-encodes the same format; any failure (unsupported/animated format, corrupt bytes, lib-load error, payload > 12MB) returns the ORIGINAL bytes. Response shape/status/cache headers/contract unchanged (backward-compat safe; iOS `?width=X` now gets a width-X image instead of full-size).
- **New `src/lib/imageTransform.ts`:** `getTransformedImageUrl` / `buildTransformedSrcSet` / `isTransformableImage` + `CARD_IMAGE_WIDTHS` / `HERO_IMAGE_WIDTHS`. Routes every remote http(s) image through the proxy; skips data:/blob:/relative.
- **OptimizedImage** refactored onto the util; added a TWO-STAGE fallback (`transformFailed` state): a failed transform srcset drops the srcset+picture sources and reloads the untouched original `src`; only a second failure escalates to the placeholder. Removed dead `generateSrcSet`.
- **Cards (criterion 2):** EventCard, RestaurantCard, Attractions inline card now pass `useTransformApi enableWebP={false} transformWidths={[...CARD_IMAGE_WIDTHS]}` so the browser fetches a card-sized candidate. HotelCard (raw img) + the three detail HERO raw imgs (Event/Restaurant/AttractionDetails) + the Index quick-view dialog img gained `srcSet`+`sizes` (heroes `sizes='100vw'` → ~viewport width).
- **CLS (criterion 1):** audited — every list card already sits in a fixed aspect-ratio/height container and every hero in a fixed-height container (h-64..h-96); no container changed, so no shift introduced.
- **Dialog prefetch (criterion 3):** Index quick-view img gated on `showEventDetails && image_url`.
- **Fallback (criterion 4):** OptimizedImage two-stage fallback + raw-img inline `onError` clears `target.srcset` to retry the original before the prior hide/gradient behavior.

Files changed:
- src/lib/imageTransform.ts (new); src/components/OptimizedImage.tsx; src/components/EventCard.tsx; src/components/RestaurantCard.tsx; src/components/HotelCard.tsx; src/pages/Attractions.tsx; src/pages/EventDetails.tsx; src/pages/RestaurantDetails.tsx; src/pages/AttractionDetails.tsx; src/pages/Index.tsx; supabase/functions/image-transform/index.ts.

- **Don't wire srcset to a proxy that doesn't resize** — it just adds a hop. The image-transform fn was pass-through; fixing the resize was the prerequisite for the whole story. Guard the resize so worst case == prior behavior.

## 2026-06-13 - WEB-PERF-005 (Split AuthContext to stop app-wide re-renders)
Auth state now lives in an external store consumed via useSyncExternalStore selectors, so a session-refresh tick no longer re-renders the whole app.

What was implemented:
- **KEY FINDING:** a state/actions context split ALREADY existed in AuthContext (from old US-082) but was DEAD code — nothing imported useAuthState/useAuthActions, all 18 importers used useAuth(), and useAuth() rebuilt `{...authState, ...actions}` on EVERY state change. Even useAuthState() re-rendered on TOKEN_REFRESHED because the whole authState object changes. So the split bought nothing; the real fix is FIELD-GRANULAR subscription.
- **External store:** new `createAuthStore(initial)` → `{getState, setState, subscribe}`. `setState` mirrors React's setter API (value OR updater fn), so every existing handler (`setAuthState(prev => ...)`) is byte-identical. Held in `useRef` (created once) → AuthProvider no longer re-renders on auth changes (it has no useState); only subscribed leaves do.
- **Stable actions:** `setAuthState = store.setState` (stable; added to the 5 callback dep arrays eslint flagged). `requireAdmin`/`getSessionExpiresAt` now read `store.getState()` at call time (removed their `authState.*` deps) so the memoized `actions` object is fully stable for `useAuthActions()` consumers.
- **Selector hook:** `useAuthSelector(selector, isEqual=Object.is)` over `useSyncExternalStore`, caching the selected value in a ref (returns the prior reference when equal) so object-returning selectors don't trip React's 'getSnapshot should be cached' loop. Added narrow `useIsAuthenticated()`/`useIsAdmin()` + module-scoped stable selectors. `useAuthState()` = identity selector. `useAuth()` = `useAuthState()` + `useAuthActions()` composed → BACKWARD-COMPAT public API unchanged, zero call-site churn.
- **Hot-path migration:** Header → `useIsAuthenticated()` + `useIsAdmin()` + `useAuthActions()`; BottomNav → `useIsAuthenticated()`.
- **Render-count test (NEW, first RTL test in src/):** src/contexts/__tests__/AuthContext.test.tsx mocks the supabase client to capture onAuthStateChange, then drives SIGNED_IN then TOKEN_REFRESHED. Asserts the narrow consumer's render count is UNCHANGED across the refresh tick (and a second one) while the combined useAuth() consumer re-renders. NUMBERS: SIGNED_IN → both render (isAuthenticated false→true); TOKEN_REFRESHED → narrow +0, combined +1.

Files changed:
- src/contexts/AuthContext.tsx (store + selectors; useState removed); src/components/Header.tsx, src/components/BottomNav.tsx (narrow selectors); src/contexts/__tests__/AuthContext.test.tsx (new).

Verification:
- npm run type-check passes; `tsc -p tsconfig.app.json` clean for these files (only the PRE-EXISTING VideoPlayer.tsx:587 parser false-positive remains). eslint on all 4 files = 0 errors (only pre-existing react-refresh + unused-caught-error warnings). Full vitest suite 100/100 pass. `npx vite build` succeeds (34s).
- Playwright auth flows NOT run in-container (no dev server/browsers/env, same constraint as prior PERF stories) — useAuth's public surface is identical so behavior is unchanged; the render-count unit test covers the new re-render guarantee.

Learnings for future iterations:
- **A "context split" is not automatically a re-render fix.** React Context has no partial subscription: any consumer re-renders when the provider value identity changes, regardless of which fields it reads. To get true per-field granularity you need an external store + useSyncExternalStore selectors (or a selector lib). The pre-existing split here was inert. See the new top Codebase Pattern.
- **`getSnapshot` MUST be cached** (return the same reference when the selected value is unchanged) or useSyncExternalStore throws/infinite-loops for any non-primitive selector. A ref-cache with an equality check covers both primitive and object selectors.
- **Backing context state with a useRef'd external store means the Provider stops re-rendering entirely** on state changes — a nice side benefit, but it means `setAuthState` is no longer a useState setter, so eslint's exhaustive-deps no longer treats it as stable; add it to dep arrays explicitly (it IS stable, so no churn).
