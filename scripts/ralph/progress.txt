Catch `unique_violation OR check_violation` and fall back to a ctid row-by-row move that DELETEs only the genuine collisions.

- **Soft-hide lifecycle pattern (is_hidden + hidden_at):** like is_merged but with a re-hide guard. The hide job only sets is_hidden where `hidden_at IS NULL`; restore (`unhide`) sets `is_hidden=false` but LEAVES `hidden_at` populated — so an admin-restored row is permanently skipped by the nightly hide job. Public sweep is small in practice because most event queries already `.gte('date', today)` (hidden ⇒ >N days past ⇒ already excluded); only queries that fetch PAST events (by-id from trending_scores, featured-without-date, the no-date sitemap lib) genuinely needed the filter. When adding `.neq('is_hidden', true)` to a `.single()` fetch, switch it to `.maybeSingle()` — the filter can now legitimately return zero rows and `.single()` throws.
- **cleanup-old-events was a hole:** it was verify_jwt=true (not in config.toml) with no admin check, so ANY authenticated user could invoke it and trigger deletes. Modernizing a cron/admin edge fn to verify_jwt=false + requireAdminOrApiKey both closes that AND lets the cron service-role bearer + admin-panel JWT through one gate.
- **archived_events (LIKE events INCLUDING ALL) is now STALE** — events has gained geom/is_merged/merged_*/recurrence_*/instance_date/is_hidden that archived_events lacks, so any `INSERT INTO archived_events SELECT *` (legacy cleanup_old_events) now fails on column mismatch. Prefer a NEW explicit-column snapshot table over `SELECT *` into a LIKE-clone.
- **Reviews live in `user_ratings` (rating + review_text), NOT a reviews/event_reviews table.** Write path: `useRatings.submitRating` (upsert onConflict user_id,content_type,content_id). ONLY public reader of user_ratings is `useRatings.fetchRatings` (feeds RatingSystem); the two GooglePlaces*Tools are admin-only. So a review visibility filter only needs to go in fetchRatings. `content_rating_aggregates` (numeric rollup) is maintained by a server trigger and is independent of review_text visibility.
- **Anonymous UGC can't self-invoke an auth-gated edge fn.** Contact submissions are mostly anon (contact_submissions.user_id null), and `supabase.functions.invoke` from an anon browser sends only the anon key → fails an owner/admin in-fn check. For anon write-path side-effects (moderation, notifications), use an `AFTER INSERT` trigger that calls the fn via `pg_net` (`net.http_post`) with the service-role bearer (`current_setting('app.settings.supabase_service_role_key')`) — server-side, works for anon, and no anon caller ever reaches paid AI. Guard the trigger body in `IF EXISTS (pg_extension WHERE extname='pg_net')` + a BEGIN/EXCEPTION WHEN OTHERS THEN NULL so a failed enqueue never blocks the insert. Logged-in UGC (reviews) CAN invoke inline with the user's JWT (owner check passes) when you want a synchronous verdict.
- **Hidden-until-scored vs default-visible:** add the visibility column with `DEFAULT 'approved'` (existing rows + old readers stay visible = backward-safe). For PUBLIC content that must be hidden until scored (reviews), have the CLIENT insert the column = 'pending' EXPLICITLY (the default only protects existing/other-path rows). For ADMIN-ONLY content (contact inbox), keep the default 'approved' and let moderation only DEMOTE — don't hide legitimate intake behind a scoring delay.
- **Job Health re-run sends `{manual:true}`** (JobHealthPanel.rerun), not your custom body. A fn with multiple modes must treat `manual===true` as its default/safe mode (e.g. a sweep), else the re-run button 400s. Other single-purpose jobs just ignore the manual flag.
- **PAUSE semantics for a GATING pipeline:** when the paused job is a visibility GATE (not a generator), pausing must TRUST-THROUGH (force-approve pending items) — otherwise pending content is stranded hidden forever. Contrast generator pipelines (article/digest) where pause just early-exits with no side effect.

**Learnings for future iterations:**
