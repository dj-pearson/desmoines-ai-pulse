# Ralph Progress Log — Admin Backend Overhaul
Started: 2026-05-20

## Codebase Patterns

### Admin edge-function auth gate (discovered 2026-05-20)
Pattern for admin-only edge functions:
1. `handleCors(req)` → early return on OPTIONS
2. `checkRateLimit(req, { windowMs, max, message })` → 429 + Retry-After
3. Reject non-GET/POST → 405
4. Build service-role client with `Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")`
5. Read `Authorization: Bearer <token>`, call `supabase.auth.getUser(token)`
6. Lookup `profiles.role` and require `admin` or `root_admin`
7. Run queries, return JSON with `Cache-Control: private, max-age=N`
Reference: `supabase/functions/process-stripe-refund/index.ts` and the new
`supabase/functions/admin-home-stats/index.ts`.

### TanStack hook for admin data (discovered 2026-05-20)
Use `supabase.functions.invoke<ResponseType>("fn-name", { body })` (not raw fetch)
so auth headers are attached automatically. Match `staleTime` to the edge
function's `Cache-Control: max-age` to avoid wasted re-fetches. Disable
`refetchOnWindowFocus` for admin dashboards — focus-thrash is noise here.

## 2026-05-20 — ADMIN-EMAIL-002 (Newsletter campaign composer + send)

Files added:
- `supabase/migrations/20260520000008_create_newsletter_campaigns.sql`
- `supabase/functions/send-newsletter-campaign/index.ts`
- `src/components/admin/NewsletterCampaignsManager.tsx`

Files modified:
- `src/pages/AdminEmail.tsx` (Campaigns tab now real)

**Learnings for future iterations:**
- Resend dispatch from an edge function: don't `Promise.all` over
  hundreds of subscribers. Batch (5 at a time is a reasonable
  default), use `Promise.allSettled` so one failure doesn't kill the
  whole batch, and cap stored error messages to the first ~5 unique
  reasons so the campaign row stays under reasonable size.
- Preview-count pattern for segment-based sends: a dedicated
  `preview_count` action on the same edge fn that takes the same
  segment shape and returns just `{ count }`. The compose UI calls
  it whenever the segment changes; saves wiring up a separate RPC.
- For HTML body input from a trusted admin, `dangerouslySetInnerHTML`
  on the preview pane is acceptable. Tag the comment so future
  readers know the trust boundary is intentional, not a miss.
- Scheduled campaign rows sit in the table with `status='scheduled'`
  until a separate worker / cron picks them up. Don't try to send
  on a schedule from the request that creates the row — that
  couples send latency to the admin's HTTP timeout.

Files modified:

- `src/pages/AdminSocial.tsx` (Queue tab now real)

Existing `social_media_posts` had every column we needed except error
tracking; reuse over a new social_post_queue table.

**Learnings for future iterations:**
- Supabase Realtime subscription pattern for an admin queue:
  ```ts
  useEffect(() => {
    const ch = supabase
      .channel("name")
      .on("postgres_changes",
          { event: "*", schema: "public", table: "…" },
          () => load())
      .subscribe();
    return () => { supabase.removeChannel(ch); };
  }, [filters]);
  ```
  Reinclude filter deps in the array so the channel rebuilds when the
  query changes — otherwise the realtime callback runs an out-of-date
  `load()`.
- Retry pattern for queue rows: don't trigger an immediate API call
  from the admin client. Reset `status → draft`, clear
  `error_message`, leave the existing cron / worker to pick it up on
  its next pass. Less risk, no secret reshuffling.
- For tri-state column filtering on a text status enum, "Failed"
  often means "row has an error_message", not a particular status
  value. Filter by `.not("error_message", "is", null)`.

## 2026-05-20 — ADMIN-SOCIAL-001 (Social account credentials manager)

Files added:
- `supabase/migrations/20260520000006_create_social_accounts.sql`
  (table + RLS service_role-only + safe view social_accounts_admin)
- `supabase/functions/manage-social-account/index.ts`
  (CRUD + test connection; AES-GCM via Web Crypto)
- `src/components/admin/SocialAccountsManager.tsx`

Files modified:
- `src/pages/AdminSocial.tsx` (tabs: Accounts ready, Queue stub)

**Required secret:** Set
`supabase secrets set SOCIAL_ACCOUNT_ENC_KEY=<base64 of a 32-byte key>`
before adding accounts. Generate with:
`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`

**Learnings for future iterations:**
- AES-GCM via the Deno Web Crypto API is simpler than pgcrypto for
  this use case: no DB extension, no SECURITY DEFINER RPC wrapper,
  and the key never leaves the edge function. Pattern: import key
  via `crypto.subtle.importKey(raw, …, ["encrypt","decrypt"])`,
  prepend a 12-byte random IV to the ciphertext, base64 the
  combined blob, store as TEXT. Decrypt is the inverse.
- "Tokens never returned to the client" pattern: stand up a safe
  view that selects every column EXCEPT the encrypted ones and
  exposes booleans (`has_access_token`) instead. RLS keeps the
  underlying table service-role-only. All writes route through an
  edge function that has both the key and the service role.
- JSX gotcha: an unbraced `>` inside text triggers a parser error.
  Wrap as `{"Stale (>24h)"}` or use the HTML entity.
- Don't add a table to types.ts unless something in the codebase
  references `Database["public"]["Tables"]["foo"]`. Local
  interfaces on the consumers are fine when the data only flows
  through edge-function-shaped responses.

**Learnings for future iterations:**

  Beats dialog forms when the user is curating 50+ rows.

  `name`.
- When extending a data-import edge function with a "skip if admin
  touched it" guard, fetch the curation flag in the existence-check
  query, not a separate round-trip.

**Learnings for future iterations:**

  must stay required in the Zod schema, even if the rest of the
  form is mostly optional. Otherwise the insert fails on the DB,
  not the form.
- When mirroring a manager pattern (Hotel → Attraction), keep
  prefixes unique (`a-name`, `h-name`) in element IDs so the two
  dialogs can coexist if ever rendered on the same page.

## 2026-05-20 — ADMIN-HOTEL-001 (Hotel admin manager: list, search, filter)

Built the first real admin manager from the new PRD. Pattern other
verticals (attractions, playgrounds) should follow.

Shape of the manager component:
1. Debounced search (`useDebounce`, 300ms)
2. Filter row (type / affiliate-presence / sort)
3. Bulk-action bar that only appears when ≥1 row is selected
4. shadcn Table with select-all-on-page + per-row checkbox
5. Status badges column collapsing Featured/Inactive/Affiliate into one cell
6. Sheet panel for read-only detail (edit dialog ships in next story)
7. Pagination (Prev/Next, 25/page, server-side via `offset` + `limit`)
8. Mobile-first responsive: hide Type/Area on <md, Rating on <lg, Updated on <xl

Files:
- `src/components/admin/HotelManager.tsx` (new)
- `src/hooks/useHotels.ts` (added `hasAffiliate` filter + `sortBy: 'updated'`)
- `src/hooks/useDebounce.ts` (new — there was no shared debounce hook)
- `src/pages/AdminHotels.tsx` (replaced placeholder with the real manager)

**Learnings for future iterations:**
- No shared `useDebounce` existed; `SearchAutocomplete.tsx` had a local
  `useDebouncedValue`. Going forward use the new
  `@/hooks/useDebounce` for any admin filter that needs debouncing.
- Don't shoehorn admin verticals into the generic `ContentTable` —
  it's tightly coupled to event-style content (writeup generator,
  domain highlights, event enhancer). Build a focused manager.
- Soft delete pattern for content tables: `UPDATE … SET is_active = false`
  inside an `AlertDialog` confirm. Preserves analytics + lets us
  reactivate without resurrecting from backups.
- When a hook is consumed in many places, prefer additive options
  (new sortBy enum value, new optional filter) over breaking the
  signature. `useHotels` is used by public pages too; the new admin
  filters default to undefined.
