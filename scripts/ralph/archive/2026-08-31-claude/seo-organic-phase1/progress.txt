## Codebase Patterns

Carried forward from the archived run in
scripts/ralph/archive/2026-08-31-claude/seo-organic-2026-08-31/progress.txt.

- Verify SEO work against the BUILD ARTIFACT, not against a function. A unit
  test over trailingSlashRedirect() passed for weeks while production did the
  opposite (SEO-004). The gates that actually catch things here read dist/:
  check-prerender-head.mjs, check-prerender-content.mjs,
  check-canonical-url-shape.mjs.
- `cmd | tail -n; echo $?` reports TAIL's exit code. Redirect to a file and echo
  $? separately when the exit code is the evidence.
- Sample the END of a sitemap, not the start. Render order and alphabetical
  order conspire to make a front-of-list sample always look healthy.
- A warning line in a build that exits 0 is invisible. Coverage regressions need
  an assertion, not a printed warning.
- Adding a route to scripts/prerender-routes.mjs requires a matching <url> in
  public/sitemap-static.xml. check-seo-route-parity.mjs enforces the subset
  relation in both directions and runs in `npm run validate`.
- `PRERENDER_ENTITIES=false npm run build` runs the hub pass only: ~4.5 min
  instead of ~12. Enough to verify anything about a hub route.
- prerender.mjs refuses to run against an already-prerendered dist/, so there is
  no prerender-only re-run. Any control experiment needs a fresh vite build.
- Probe PostgREST for columns before deriving schema from a hook's TS interface.
  `restaurants` has `location` and `city`, NOT `address`, and the interface in
  the hook does not tell you that.
- A hub page's JSON-LD is not gated post-build; only the prerender strict gate
  checks it. That gate is now ON for the hub pass, and a hub rejection fails the
  build via the missing-on-disk assertion.

**Learnings for future iterations:**
- The strict gate was entity-only; static hub routes rendered with strict=false.
  That is why a hub could ship as a shell without failing anything: the only
  JSON-LD assertion in this repo lives inside the prerenderer. Turning it on for
  hubs was a one-argument change, safe only because all 40 existing routes
  already carried a canonical and at least one ld+json - checked in dist/ first,
  not assumed.
- The six pages had a per-route canonical on production while having no
  canonical in their source. That comes from the SPA-fallback rewrite, so "the
  canonical looks right in curl" says nothing about whether the page declares
  itself. The strict gate reads the rendered document and caught the real state.
- These pages were not missing from the prerender list by accident - they were
  in NEITHER list. A route can exist in App.tsx, be linked from the nav, and be
  invisible to both systems that decide what gets indexed.
- `restaurants` has no `address` column. The hook's TS interface and the
  generated types will let you write one anyway; the PostgREST probe takes five
  seconds and is the only thing that answers it.
