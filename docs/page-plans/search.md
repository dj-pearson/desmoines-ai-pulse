# Search: action plan

Scope: `/search` (`src/pages/SearchResults.tsx`), `/search/advanced` (`src/components/AdvancedSearchPage.tsx`), the `nlp-search` edge function behind them, every box that lands on `/search` (home hero via `NLPSearchBar`, hub autocompletes, the missing header search), and saved searches and alerts (`SaveSearchButton`, the dashboard tab, `saved-search-alerts`).
Inputs: the holistic audit plus five section audits (results, advanced, entry points, saved searches, platform). Every P0 and P1 was re-opened at its cited line on 2026-09-25. Production state comes from `scripts/db-snapshot.json` (captured 2026-08-24) and `docs/RLS_AUDIT.md`. No live probe was available, so run `npm run check-schema:probe` before merging anything that names a column, and before any deferred item.

## Where it stands

- **The AI path probably fails on every query.** `nlp-search` ends with `await supabaseClient.from('search_analytics').insert({...}).catch(...)` (`supabase/functions/nlp-search/index.ts:389-410`). The installed postgrest-js 2.116 builder defines `then` and nothing else (`node_modules/@supabase/postgrest-js/dist/index.mjs:391`), so `.catch` is undefined, the call throws inside the outer `try`, and the function answers 500 (`:428-436`) after the Claude call and all three table reads have run. The deployed function pins `supabase-js@2.53.0` from esm.sh (`:4`), which nobody here opened, so this is unconfirmed live. If it holds, every `/search` visit shows the red "AI search is temporarily unavailable" alert (`SearchResults.tsx:298-309`) and no NLP search has ever been logged. Every spec stubs or aborts the function (`tests/search-request-loop.spec.ts:30`, `tests/home-search.spec.ts:66`), so CI can't see it.
- **Behind that, the queries are wrong in ways the page then reports as fact.** Attractions filter on `category` (`:378`), which the snapshot doesn't have (the column is `type`), so the 42703 is swallowed (`:381-383`) and places never come back. The keyword filter only runs when `confidence > 0.5` (`:307,352,377`); the parse-failure fallback sets 0.3 (`:237`), so a low-confidence query returns the next 20 events, the 20 top-rated restaurants and the first 20 attractions A-Z as "results". "Free" matches `price.is.null` (`:303`). Restaurants skip `is_merged` and `status` (`:317-323`), and attractions skip `is_active` (`:363-368`), under a service-role key that bypasses RLS.
- **The page loses what the function does return.** Cards link `/${type}/${item.id}` (`SearchResults.tsx:45,53`), and `/attractions/:slug` resolves by slug or `createSlug(name)`, never id (`src/lib/resolveBySlug.ts:40-70`), so every attraction result is Not Found. Event cards never show a date although `CardItem` declares one (`:36,79-99`). Up to 60 mixed cards sit in one grid with no grouping (`:315-321`). "Understood:" reads back `getIntentSummary()`, which lists kid-friendly, pet-friendly and near-downtown (`useNLPSearch.ts:305-327`), none of which the function applies. The count is the per-type cap, not a match count (`:293`). Search runs through a `useMutation` (`useNLPSearch.ts:186`), so Back re-runs the Claude call and a slow response for one query can overwrite a newer one.
- **`/search/advanced` sells filters that do nothing.** The Insider gate promises "distance, price range, rating, time of day, and accessibility filters" (`AdvancedSearchFilters.tsx:229`), and `UpgradeModal.tsx:54` repeats it. `filterByLocation` returns its input (`useAdvancedSearch.ts:418-423`), `openNow` is an empty block (`:313-316`), and radius, price, time of day, features, deals and accessibility are never read. There's no query box at all. Geolocation is requested on mount (`:99-113`) and never used.
- **Saved searches are three shapes in one table.** `/events` writes `{q, category, location, price, preset, sort}` as `event_list` through `create_event_saved_search`. `/search/advanced` inserts the `AdvancedSearchFilters` shape as `advanced`. iOS writes `{query, tab, alerts_enabled}` and picks `event_list` for its Events tab and `advanced` for every other tab (`ios/DesMoinesInsider/Services/SavedSearchService.swift:54-56`). `useAdvancedSearch.loadSavedSearches` loads all of them (`:119-124`), and `SavedSearches.tsx:53` reads `filters.features.length`, so one save from `/events` or from the iOS app crashes `/search/advanced` for that user. The nightly matcher reads `q` (`saved-search-alerts/index.ts:80`), so an iOS Events-tab search, which stores `query`, matches every new event. It compares an area slug like `west-des-moines` as a substring of "West Des Moines" (`:84-88`), which never matches. Every event in the email links to bare `/events` (`:353`). `last_alerted_at` advances even when the send failed (`:313-314`). `/search`, where the hero now sends people, has no save or alert at all.
- **Worth keeping:** the WEB-QA-027/033 fixes (non-rejecting, identity-stable `search`) and the request-count spec that guards them; rate limiting before any Claude call (`index.ts:126-132`); `sanitizePostgrestPattern` on every interpolated value; the Central `dateWindow.ts` and its test; the event visibility predicate (`:278-281`); the "Keep typing" state (`SearchResults.tsx:329-340`); noindex,follow; the keyword fallback, which uses FTS plus fuzzy and is the better search today; `resultHref`, `loosenQuery` and `orderExamplesForHour`, which the home bar already uses; the server-side tier gate and limit on saved searches (RPC plus `trg_saved_searches_limit`).

## What makes it ours

1. **It shows what it understood, and lets you fix it.** `nlp-search` returns `appliedFilters`, the constraints it actually turned into SQL, and `/search` renders each as a removable chip ("Tonight", "Free", "Events"). Anything parsed but not applied shows as muted text ("Not filtered: pet-friendly"). Removing a chip re-runs the search from the stored intent with no model call. Yelp, Eventbrite, Catch Des Moines and TripAdvisor all hide what their search box understood; this one is checkable. Built on `supabase/functions/nlp-search/index.ts`, the `parsedIntent` it already returns, and `useNLPSearch.getIntentSummary`'s labels. WP1 and WP2.
2. **One box for the whole evening.** For an event result with a start time and coordinates, the card carries "Dinner nearby: <restaurant>, 0.3 mi, open at 6:00 PM" from `pickDinner` and `restaurantBoxes` (`src/lib/tonightPairings.ts`), which read the stored `restaurants.opening` hours and lat/lng, and "Stay: <hotel>, 0.4 mi (straight line)" from `useHotelPins()` and `haversineDistance` (`src/lib/geo.ts`). Hotels become a searchable type (`hotels` has `slug`, `area`, `is_active` in the snapshot; `/stay/:slug` is routed at `App.tsx:543`). Eventbrite has no restaurants, Yelp has no events, and none of them puts lodging next to a show. WP1 and WP2.
3. **"Tell me when this shows up."** Any `/search` that includes events can be watched from the results page. It saves the applied keywords, category and free flag through the existing `create_event_saved_search` RPC, and the nightly `saved-search-alerts` job emails new matches, now with links to the events themselves and area matching that works. Eventbrite alerts follow organisers and Catch Des Moines has none; this follows the visitor's own words. Built on `src/hooks/useSavedSearchAlerts.ts`, `SaveSearchButton`'s upgrade path, and `supabase/functions/saved-search-alerts/index.ts`. WP3 and WP5.
4. **A fast first answer that gets smarter.** `/search?q=` paints keyword results from the indexed paths the hubs already use (`useEvents` FTS plus `fuzzy_search_events`, `useRestaurants`, `useAttractions`, `useHotels`) while the AI parse runs, then swaps in the understood set, labelled. The TanStack cache keyed on the query makes Back instant and costs no second Claude call. A competitor's search box is either keyword-only or a spinner. WP2.

## WP1: `nlp-search` returns true results (edge function; deploy is D1)

**Goal:** a successful parse returns 200 with results that match the query, and the response says which filters it applied.

**Files:** `supabase/functions/nlp-search/index.ts`, new `supabase/functions/nlp-search/search.ts` (pure helpers plus an exported `handleSearch(req, deps)`), new `supabase/functions/nlp-search/search.test.ts`, new `supabase/functions/nlp-search/handler.test.ts`.

1. **P0 / S. Stop the 500.** Replace the `.catch` chain (`index.ts:389-410`) with `const { error: logErr } = await ...insert(...)` and a `console.warn` on `logErr`, then take it off the response path with `EdgeRuntime.waitUntil` when it exists. Move the handler body into `handleSearch(req, { client, fetch, now })` in `search.ts` so `index.ts` is just `serve((req) => handleSearch(req, realDeps))`. `handler.test.ts` runs it with a stub client whose builders are thenables with no `catch` (the real shape) and a stubbed Claude `fetch`, and asserts status 200, `success: true`, and one analytics insert.
2. **P0 / S. Attractions return places.** `category.ilike` becomes `type.ilike` and `location.ilike`, matching `attractionSearchFilter` (`src/hooks/useAttractions.ts:52-56`). Add `.eq('is_active', true)`. Log every per-type error instead of dropping it (`:285,356,381`), and add `errors: { events?: string, ... }` with a fixed code, not the message, so the page can tell "none" from "failed".
3. **P1 / S. Never return unfiltered rows.** Drop the `confidence > 0.5` gate on the keyword predicate (`:307,352,377`). Low confidence skips only the structured facets (category, date, location). With no usable keywords, return empty with `matchType: 'keyword'` and `reason: 'unparsed'`. Events and restaurants match through `.textSearch('search_vector', q, { type: 'websearch', config: 'english' })` (both columns are in the snapshot), falling back to a title/name plus venue ILIKE when that returns nothing. Attractions and hotels, which have no `search_vector`, AND an ILIKE per token. This supersedes the per-token item in `home.md:284`.
4. **P1 / S. Visibility for every type.** Restaurants: `.neq('is_merged', true)` (the column is `NOT NULL DEFAULT false`, `20260612000008_dedupe_columns.sql:15`) and `.or('status.is.null,status.neq.closed')`. A bare `.neq('status','closed')`, as two audits suggested, would also drop every row whose status is NULL. Return `status` and `opening_date` so the card can say "Opening soon". Attractions: `is_active = true` (item 2). Hotels: `is_active = true`.
5. **P1 / S. "Free" means free.** Use `price.ilike.%free%,price.eq.$0,price.eq.0`, the same string as `FREE_PRICE_FILTER` (`src/lib/eventPrice.ts:19`). `search.test.ts` reads that file and asserts the two strings are equal, so they can't drift.
6. **P1 / M. `appliedFilters` and `unappliedFilters`.** Build each entry next to the `.eq/.or/.in/.gte` call that applies it, never from the parse. Everything in `ParsedSearchIntent` that no predicate uses (kidFriendly, petFriendly, dateFriendly, nearDowntown, outdoorSeating, liveMusic, dietary, timeOfDay, maxBudget on events) goes into `unappliedFilters` as a label. Apply the two the data supports now: `kidFriendly` becomes `attractions.is_kid_friendly = true` and `priceRange: 'free'` also sets `attractions.is_free = true`. Both columns are in the snapshot.
7. **P1 / S. Validate the input and the model.** Clamp `query` to 200 characters and collapse whitespace before it reaches the prompt or the log (`:100-110,138,153`). Clamp, don't reject: a new 400 would tighten validation for shipped callers. Reject a non-string `query` with the existing 400. Add `coerceIntent(raw, requestedTypes, query)` in `search.ts`: keep known enum values only, default `keywords` to the query's tokens, intersect `contentTypes` with the request (falling back to the request when the intersection is empty), clamp `confidence` to 0-1. Today a response with no `keywords` throws at `:262`. The 500 body becomes `{ success: false, error: 'Search failed', code: 'ai_unavailable' | 'bad_request' | 'internal' }`; the status codes stay as they are.
8. **P1 / S. A slow model doesn't hold the page.** Claude timeout 60s (`:206`) becomes 3.5s. On timeout, a non-OK status or a parse failure, run the keyword path with `coerceIntent`'s defaults and return 200 with `degraded: true` and `matchType: 'keyword'`. This is `home.md:284`'s timeout and fallback. The only callers are the web app (`grep -rn nlp-search ios android` is empty), so the move from 500 to 200 breaks no shipped binary.
9. **P1 / M. Hotels.** Accept `'hotels'` in `contentTypes`, add it to the prompt's allowed values, and query `hotels` (`id, name, slug, area, city, short_description, image_url, avg_nightly_rate, star_rating, latitude, longitude`; every column is in the snapshot) with `is_active = true`, the area filter and the token ILIKE on `name`, `area` and `short_description`. It's additive: a caller that doesn't ask for hotels never gets the key.
10. **P1 / S. Skip the model when the intent is given.** An optional `intent` request field goes through `coerceIntent` and replaces the Claude call. It's what chip removal sends (WP2 item 5). Rate limiting still runs first.
11. **P2 / S. Latency.** Run the per-type queries with `Promise.all` (they're awaited in series at `:285,356,381`). Log the query length, not the text.

**Acceptance:**
- `handler.test.ts` gets a 200 with `success: true` from a stub client whose `insert()` has no `.catch`.
- A stubbed intent with `confidence: 0.2` and keywords `['jazz']` produces an events query that still carries the text predicate.
- `rg "category\.ilike" supabase/functions/nlp-search` is empty.
- `appliedFilters` never names a filter that has no predicate: the test runs the full example list (`NLP_SEARCH_EXAMPLES`) through canned intents and checks each label against the recorded query calls.
- A request without `hotels` produces a body with no `results.hotels` key.

**Verify:** `deno test supabase/functions/nlp-search/` (the existing `dateWindow.test.ts` plus both new files), `deno check supabase/functions/nlp-search/index.ts`, `npm run check-schema` for the column strings. After D1 deploys, one `curl` against the deployed function with a real query must return 200.
