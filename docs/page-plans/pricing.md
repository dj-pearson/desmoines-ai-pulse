# Pricing & Premium: action plan

Scope: `/pricing` (`src/pages/Pricing.tsx`), `/subscription` (`src/pages/SubscriptionPortal.tsx`), `/subscription/success` (`src/pages/SubscriptionSuccess.tsx`), the in-app premium surfaces (`src/components/PremiumGate.tsx`, `src/components/UpgradeModal.tsx`, `src/hooks/useSubscription.ts`, `src/lib/premiumFeatures.ts`), and the server code that decides money: `create-subscription-checkout`, `manage-subscription`, `stripe-webhook`, `subscription-lifecycle`.
Inputs: one holistic audit and five section audits (pricing page, checkout, portal, gates, platform). Every P0 and P1 was re-opened at its cited line on 2026-09-25. Production state comes from `scripts/db-snapshot.json` (captured 2026-08-24), `.github/migration-drift-baseline.json` and `docs/RLS_AUDIT.md`. There was no live probe, so run `npm run check-schema:probe` before any deferred item.

CLAUDE.md "Money is decided on the server" governs every item below: the browser displays prices, quotes and trial terms, and never computes an amount that reaches Stripe or a row. iOS and Android read tier from `user_subscriptions` joined to `subscription_plans(name)` with `status = 'active'` (`StoreKitService.swift:580-583`, `BillingService.kt:628-632`), and `MIN_SUPPORTED_APP_VERSION` is 1.0.0, so the plan names `insider`/`vip`, the status vocabulary and the `is_active` read path are frozen.

## Where it stands

- **A plan change takes the money and grants nothing.** For an existing web subscriber, one click on another tier runs `stripe.subscriptions.update` with prorations (`create-subscription-checkout/index.ts:270-282`) and relies on the webhook to move the row. The webhook writes `subscriptionUpdatePatch`, which leaves out `plan_id` on purpose (`_shared/stripeSubscriptionRow.ts:109-121`, `stripe-webhook/index.ts:589-596`). An Insider who clicks "Go VIP" pays VIP and stays Insider on web, server and both apps. The proration preview is computed (`:255-268`) and returned only after the charge, and no client reads it. Downgrades go the same way, immediately, which contradicts the FAQ at `Pricing.tsx:151`.
- **Dunning can bill twice.** `subscription-lifecycle` flips a past_due row to canceled at period end plus 7 days (`index.ts:28`, `:200-205`) without touching Stripe, while entitlements use 14 (`_shared/entitlements.ts:15`, `useSubscription.ts:75`). Stripe keeps retrying the old subscription, and checkout's guard reads only active or trialing rows (`create-subscription-checkout/index.ts:179`), so a member who resubscribes after the "paused" email gets a second live subscription.
- **Four surfaces still sell what WEB-FEAT-016 withdrew.** UpgradeModal lists "Early access to events" and four VIP perks (`UpgradeModal.tsx:104`, `:107-112`). The screen shown right after payment lists eight undelivered benefits (`SubscriptionSuccess.tsx:43-64`). The SEO description promises "early event access" and "exclusive VIP perks" (`Pricing.tsx:276`). The portal's free-plan copy says "early access to events" (`SubscriptionPortal.tsx:340-341`). The truthfulness test reads only `text: "..."` literals in Pricing and the `featureDescriptions` keys in the modal (`plan-features-truthful.test.ts:84-102`, `:137-145`), which is how all four got through.
- **The headline Insider benefit can't be used.** "AI Trip Planner" is Insider's first highlighted line (`Pricing.tsx:84`), but `AI_PLANNER_AVAILABLE = false` (`src/lib/tripPlannerStatus.ts:10`) and `trip_plans` isn't in the snapshot. The comment at `Pricing.tsx:80-81` says no quota exists; `generate-itinerary/index.ts:15-19,185-213` enforces Insider 5 a month and VIP unlimited.
- **The first screen is broken on a phone.** `index.html:153-158` paints every `h1` `#fff`, and the Pricing H1 (`:302`) has no colour class, so it renders white on the light hero. The Success (`:78`, `:109`) and Portal (`:201`) H1s inherit the same rule. Anonymous visitors see "Current Plan" on the Free card because `tier` is `'free'` with no user (`useSubscription.ts:204`, `Pricing.tsx:481`).
- **Failures are silent.** `Pricing.tsx:243` reads `checkoutError` from the render closure, so the first failure shows nothing, and `useSubscription.ts:295-296` replaces the server's body with supabase-js's generic non-2xx text. The 403 `email_verification_required` that every fresh signup hits never reaches them. After Cancel or Resume the portal keeps the old state: the mutation invalidates `["user-subscription"]` (`usePayments.ts:282,301`) while the data lives under `["user-subscriptions", id]`, and `refetchOnWindowFocus` is off (`main.tsx:239`).
- **The billing tabs read tables that don't exist.** `payments`, `invoices` and `get_user_payment_summary` are absent from the snapshot, and both migrations are in the drift baseline (`.github/migration-drift-baseline.json:31-32`). Two of three portal tabs can only show ErrorState, and every webhook payment log write fails quietly (`stripe-webhook/index.ts:699-708`).
- **Worth keeping:** `decision.ts` and its check order, first-purchase-only trials (`_shared/trialEligibility.ts` plus the Stripe history read), fail-closed guard reads that refuse with 503, webhook signature and event-id ledger, fail-closed `premiumFeatures.ts`, the PremiumGate loading hold, WEB-FEAT-015 store deep links, the pre-CTA renewal disclosure, and the removal of fake testimonials.

Two decisions stay with the owner and this plan doesn't take either. **Search D2** decides whether "Advanced search filters" stays on Insider (`Pricing.tsx:86`, `docs/page-plans/search.md:188`). **VIP** today differs from Insider only by an unlimited saved-search cap (Insider 10, `create_event_saved_search` in `20260623000003` and `20260925000002`) and, once the planner returns, unlimited trip plans. Whether that's worth $12.99 or the tier should be withdrawn is D-VIP below.

## What makes it ours

1. **A plan page that can't lie, and says so.** Every benefit line on Pricing, the modal, the success screen and the portal comes from one module, `src/lib/planBenefits.ts`, which only holds lines for keys in the `DELIVERED` map of `plan-features-truthful.test.ts`. The test scans all four files for withdrawn phrases, not just `text:` literals. Each line links to the thing it unlocks ("Saved-search alerts" opens `/search`, "AI trip plans" opens `/trip-planner`). The page carries one plain sentence: "Every line here is checked against the code that enforces it." Yelp, Eventbrite, TripAdvisor and Catch Des Moines sell with adjectives. Files: `planBenefits.ts`, `plan-features-truthful.test.ts`, `premiumFeatures.ts` (read). WP1, WP2.
2. **Who bills you, stated plainly.** For a signed-in visitor, `/pricing` opens with their own plan: tier, who bills it (Stripe, App Store or Google Play) and where to manage it, from the per-platform rows `useSubscription` already returns and the `manageAt`/`manageUrl` that `manage-subscription` already sends. A checkout refused with `store_subscription_active` says "You already have Insider through the App Store" with the store link, instead of a spinner. Files: `useSubscription.ts`, `SubscriptionPlatformBreakdown.tsx` (pattern), `manage-subscription` (existing response). WP1, WP2, WP3.
3. **Your own numbers, not tiles.** A signed-in free user sees "3 of 3 favorites saved" and "Saved searches: Insider 10, VIP no limit" from `useSavedCount` (Account plan, read-only) and `subscription_plans.limits`, which `useSubscription` already fetches. Nothing is estimated; a failed count hides the line. Files: `src/hooks/useSavedCount.ts` (read), `useSubscription.ts`. WP2.
4. **The next charge, from Stripe, before it happens.** The portal says "Trial ends Oct 2, then $4.99" or "Renews Oct 25 for $4.99" from `trialEnd`, `currentPeriodEnd` and `upcomingInvoice`, which `manage-subscription` details already returns (`index.ts:389-415`). Files: `SubscriptionPortal.tsx`, `create-subscription-checkout/index.ts`. WP3 now, WP5 plus D2 later.

## How the packages fit together

The one existing spec this plan edits, `tests/subscription-checkout.spec.ts`, belongs to WP2.
