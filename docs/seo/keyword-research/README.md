# Keyword seed list for the volume pull

377 candidate terms, generated by `scripts/generate-keyword-seeds.mjs`. Regenerate after editing
that script; do not hand-edit the CSVs.

| File | Use |
|---|---|
| `keyword-upload-list.csv` | One `keyword` column. Upload to Keyword Planner (Get search volume and forecasts), Ahrefs Keywords Explorer, or Semrush Keyword Overview bulk. Under the 1,000-row cap for a single upload. |
| `keyword-seed-master.csv` | Same keywords with the classification. Join volume back on `keyword` (all lowercase, single-spaced, no punctuation beyond digits). |

## Why these terms and not others

Catch Des Moines is the CVB. It wins city-level head terms on domain authority, and the
2026-08-28 plan measured us at position 30-57 with zero clicks on every one of them. Nothing here
tries to take those. Every cluster is a place where the incumbent is structurally weak rather than
merely ahead, and `catchdm_gap` records which kind:

| `catchdm_gap` | The weakness |
|---|---|
| `needs-hours-data-cvb-lacks` | Answer requires opening hours we hold and they do not |
| `needs-attribute-data-cvb-lacks` | Same, for dietary and amenity attributes |
| `requires-freshness` | Page is only correct if rebuilt weekly or monthly |
| `suburb-out-of-cvb-scope` | Ankeny, Waukee, Grimes residents searching their own town |
| `cvb-has-no-neighborhood-pages` | No East Village, Beaverdale, Valley Junction pages exist |
| `cvb-targets-visitors-not-parents` | Playgrounds and kids, our best-positioned module |
| `no-one-answers-logistics` | Parking, nearby food, schedules per venue |
| `seasonal-editorial-cvb-thin` | Format already proven on this domain by the patio guide |
| `answer-format-cvb-does-not-publish` | Question shape, and they emit no JSON-LD anywhere |
| `cvb-dominates-do-not-target` | Control rows only, so the tail has a baseline to sit against |

## Reading the numbers when they come back

Without an active spending ad account, Keyword Planner returns 500,000 / 50,000 / 5,000 / 500 / 50
and nothing between. Treat volume as an order of magnitude, never as a traffic forecast. The
2026-08-28 plan has the full note on this.

The ranking signal to compute after the join is volume divided by competition, filtered to
`route_status` of `live` or `pseo-slug` — those are terms where the page already resolves and only
the content is missing, which is the cheapest work on the board.

## Columns

- `cluster` / `subcluster` — grouping for the build plan
- `intent` — discovery, logistics, research, transactional
- `seasonality` — evergreen, recurring, monthly, seasonal-{season}
- `target_route` — where the term should land
- `route_status` — `live` (route in App.tsx), `pseo-slug` (in `scripts/pseo-slugs.txt`),
  `route-exists-no-content` (dynamic segment resolves, nothing published behind it)
- `priority` — 1 build now, 2 next, 3 measure before committing
