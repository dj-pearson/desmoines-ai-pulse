# Lane: ios

**Mission.** The iOS app matches the web on core journeys and never gives App Review a reason to reject it.

**Owns.** ios/DesMoinesInsider/**, ios/DesMoinesInsiderTests/**, ios/project.yml

**Backlog.** Open stories in `prd.json` with prefix IOS-AUDIT-*, XPLAT (iOS half). See `../README.md` for the loop.

## Handoff

None. `/stay/near/<venue>` and the hub detail pages (`/music/venues/<slug>`, `/sports/<slug>`, `/outdoors/<slug>`) are the shared pages that still open on the web; a native venue, team or trail screen would replace the `hubDetailPrefixes` entry with a case, and `iosHubDetailParity.test.ts` lists what the web has. Neither the kids filter (`SearchFilters.kidsOnly`) nor date night (`SearchFilters.dateNight`) is written into a saved search: the web's saved-search keys and the alert job have no key for either, so saving with that chip keeps only the keyword. Date night's evening rule filters on the device from a 60-row page (as Open Now does for restaurants), so a fortnight with more than 60 matching rows can show fewer than 20 evenings. `/map` opens the Map tab with the link's `layers` and `when`; its `sel` (a bare row UUID with no kind, so a native lookup would have to try three tables) and `bbox` (the Map tab's camera has no URL form) are ignored, and a link naming playgrounds or trails opens the web map until the native map draws them (`MapLinkLayers.webOnlyKeys`).
